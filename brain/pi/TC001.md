# TOPDON TC001 → Pi → Sentinel Sensors

本接入仅针对 **TOPDON TC001**。使用 Linux V4L2 原始数据，由 Pi 解析温度并
提供热像视频；PC 继续通过现有 Wi-Fi 或网线连接 Sentinel。

## 接线

TC001 → 支持数据传输的 USB-C 转 USB-A 转接头/延长线 → Pi 的 USB-A 主机接口。
Pi 继续使用自己的 USB-C 电源。Pico 与普通摄像头继续接在各自的 USB 接口。
请先确认转接件支持 USB 数据，只有供电功能的线不能读取摄像头。

保留原有 `userinfo.json`、`probeconfig.json` 和
`event_log.csv`；如果已有 `sentinel_history.sqlite3` 也要保留。Pico 的 `main.py` 不需要修改。

先在运行旧服务的终端按 Ctrl+C 停止旧服务，切到相同的 Python/conda 环境和
程序目录。先检查是否已有 OpenCV 和 NumPy：

```bash
python -c "import cv2, numpy; print(cv2.__version__)"
```

若检查成功，可沿用现有依赖；缺少依赖的环境可安装：

```bash
conda install -c conda-forge flask pyserial numpy opencv
```

非 conda 环境可用 `python -m pip install -r requirements-thermal.txt`；不要在同一
环境中同时安装 conda 的 `opencv` 和 pip 的 `opencv-python-headless`。

安装设备查看工具：

```bash
sudo apt update
sudo apt install v4l-utils
```

不要混装 `opencv-python` 与 `opencv-python-headless`。如果原有环境已经能
`import cv2`，优先保留原来的 OpenCV；本模块需要 NumPy 和支持 V4L2 的 OpenCV。
`requirements-thermal.txt` 是干净环境的依赖清单。

## 确认设备

插上 TC001，在 Pi 终端运行：

```bash
lsusb
v4l2-ctl --list-devices
python tc001_reader.py --probe
```

自动识别参考 USB ID `0bda:5830` 或包含 TC001 的设备名。这个 ID 不能代替型号
核实；不同硬件修订版可能需要手动指定设备。`--probe` 不打开摄像头，不影响
现有采集。找到 TC001 对应的 `/dev/videoX` 后检查格式，例如实际是 video2 时：

```bash
v4l2-ctl --device /dev/video2 --list-formats-ext
```

应支持 **YUYV 256×384**（上半图像，下半温度数据）。同一相机可能列出多个
节点，应选视频采集节点。不要把 `/dev/video2` 当成固定编号。

## 启动

现在运行普通启动命令就会自动检测 TC001，无需每次设置环境变量：

```bash
python app.py
```

未插入时显示离线并每 3 秒重新检测，插入后自动尝试连接。希望整个服务在 Pi
开机后自动运行，参见 [开机启动](AUTOSTART.md)。

如未识别，使用上一步查到的实际节点，例如：

```bash
THERMAL_DEVICE=/dev/video2 python app.py
```

也可指定 `/dev/v4l/by-id/` 下对应的视频设备链接，减少重新插拔后编号变化的
影响。未设置 `THERMAL_DEVICE` 时默认 `auto`；手动指定设备的设置仅对本次
命令有效。需要关闭热像功能时用 `THERMAL_DEVICE=off python app.py`。
不要同时运行另一个热像查看器占用同一相机。

如果普通摄像头的编号也变了，可以分别指定两台设备（示例编号必须替换）：

```bash
CAMERA_DEVICE=/dev/video0 THERMAL_DEVICE=/dev/video2 python app.py
```

默认普通摄像头会避开识别到的 TC001。原来的 `CAMERA_INDEX` 参数仍可使用。
如果报设备权限错误，检查 `ls -l /dev/videoX` 和 `groups`；需要时请将运行服务
的用户加入 `video` 组，重新登录后再启动。

## 页面和接口

Pi 上先打开 `http://localhost:8000/api/thermal`。
成功时 `available` 应为 true，并包含 `min_c`、`max_c`、`mean_c`、`center_c`。
若为 false，查看 `error`；不要用空值或离线值当成测量结果。

Sentinel → Sensors 会出现 **TOPDON TC001** 卡片：

- 预览热像，显示全画面最高温度。
- 点击卡片查看大图、最低/平均/中心温度，并设置名称及告警阈值。
- 阈值、首页曲线和状态变化日志使用 **全画面最高温度**。
- 卡片可与普通摄像头、DS18B20、门磁同时显示。
- 断开或超过 3 秒没有新帧时，接口温度清空，视频停止。重新插入后后台重试，
  网页在下一次传感器轮询后恢复。

接口：`/api/thermal`（状态）、`/thermal_feed`（MJPEG）、
`/api/sensors`（包含 `id=thermal:tc001` 的温度记录）。所有客户端共享一个采集
线程，每秒最多生成约 10 帧预览；传感器数值沿用网页每 3 秒刷新。

## 测量和验证范围

下半帧按小端 16 位数据解码，温度换算为 `raw / 64 - 273.15` °C。
彩色图由温度矩阵生成，色阶随当前画面最低/最高温度变化；图像显示为 512×384，
实际热像分辨率仍为 256×192。异常像素显示为黑色，不用于统计；温度平面明显
异常或收到 RGB 数据时直接报错，不生成伪温度。

此版本使用社区验证的 TC001 原始读取格式，尚未在你的实物上验证；没有实现
TOPDON App 中完整的发射率、反射温度和距离修正。部署后应使用同一目标与
TCView/TopInfrared 对照检查读数，再确定实验告警阈值。

协议参考：[PyThermalCamera 作者项目](https://github.com/leswright1977/PyThermalCamera)、
[原始数据解析示例](https://github.com/leswright1977/PyThermalCamera/blob/main/src/tc001v4.2.py)。
产品信息：[TOPDON TC001](https://www.topdon.com/products/tc001)。

本项目独立实现采集、缓存、接口与页面接入，没有直接引入上述项目的程序文件。
