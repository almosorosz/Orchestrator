# TOPDON TC001 → Pi → Sentinel Sensors

This integration supports **TOPDON TC001** only. The Pi decodes temperature readings from Linux V4L2 raw data and serves thermal video. The PC continues to connect to Sentinel using the existing Wi-Fi or Ethernet connection.

## Wiring

TC001 → USB-C-to-USB-A adapter/extension cable with data support → Pi USB-A host port. Continue powering the Pi through its own USB-C power supply. Keep the Pico and ordinary camera connected to their respective USB ports. Confirm that the adapter supports USB data; power-only cables cannot read the camera.

## Files to update on the Pi

Update or add the following in the directory containing the Pi's existing `app.py`:

- `app.py`
- `tc001_reader.py` (new)
- `fumehood_dashboard.html`
- `requirements.txt`, `requirements-thermal.txt` (new)
- `pico_serial_reader.py` (Pico connection, retry, and error messages are now in English)
- `install_autostart.py`, `AUTOSTART.md` (optional automatic startup setup)
- `history_store.py`, `HISTORY.md` (continuous recording, PC saving, and cloud sync folder copies)

Preserve the existing `userinfo.json`, `probeconfig.json`, and `event_log.csv`. Preserve `sentinel_history.sqlite3` if it already exists. The Pico's `main.py` does not need changes.

First press Ctrl+C in the terminal running the old service to stop it, then switch to the same Python/conda environment and program directory. Check whether OpenCV and NumPy are already available:

```bash
python -c "import cv2, numpy; print(cv2.__version__)"
```

If this succeeds, keep the existing dependencies. If dependencies are missing, install them with:

```bash
conda install -c conda-forge flask pyserial numpy opencv
```

For a non-conda environment, use `python -m pip install -r requirements-thermal.txt`. Do not install conda's `opencv` and pip's `opencv-python-headless` in the same environment.

Install the device inspection tools:

```bash
sudo apt update
sudo apt install v4l-utils
```

Do not install both `opencv-python` and `opencv-python-headless`. If the existing environment can already `import cv2`, prefer keeping its OpenCV installation. This module requires NumPy and an OpenCV build with V4L2 support. `requirements-thermal.txt` lists dependencies for a clean environment.

## Identify the device

Connect the TC001 and run these commands in the Pi terminal:

```bash
lsusb
v4l2-ctl --list-devices
python tc001_reader.py --probe
```

Automatic detection uses USB ID `0bda:5830` or a device name containing TC001. This ID does not replace model verification; different hardware revisions may require manually specifying a device. `--probe` does not open the camera or interrupt existing acquisition. After finding the TC001's `/dev/videoX` node, check its formats. For example, if the actual node is video2:

```bash
v4l2-ctl --device /dev/video2 --list-formats-ext
```

It should support **YUYV 256×384** (image data in the upper half, temperature data in the lower half). A camera may expose multiple nodes; choose its video capture node. Do not assume `/dev/video2` is a fixed device number.

## Startup

The ordinary startup command now detects the TC001 automatically, without requiring environment variables each time:

```bash
python app.py
```

When the device is absent, it shows as offline and detection retries every 3 seconds. Connecting the device triggers an automatic connection attempt. To start the entire service automatically when the Pi boots, see [Automatic startup](AUTOSTART.md).

If detection fails, specify the actual node found above, for example:

```bash
THERMAL_DEVICE=/dev/video2 python app.py
```

You can also specify the corresponding video device link under `/dev/v4l/by-id/` to reduce the impact of device numbering changes after reconnection. When `THERMAL_DEVICE` is unset, it defaults to `auto`. A manually specified device applies only to that command invocation. To disable thermal imaging, use `THERMAL_DEVICE=off python app.py`. Do not run another thermal viewer that occupies the same camera at the same time.

If the ordinary camera's device number also changes, specify both devices separately (replace the example device numbers):

```bash
CAMERA_DEVICE=/dev/video0 THERMAL_DEVICE=/dev/video2 python app.py
```

By default, the ordinary camera selection avoids a detected TC001. The original `CAMERA_INDEX` option is still supported. If device permission errors occur, check `ls -l /dev/videoX` and `groups`. If necessary, add the service user to the `video` group, log in again, and restart.

## Page and endpoints

First open `http://localhost:8000/api/thermal` on the Pi. On success, `available` should be true, and the response should include `min_c`, `max_c`, `mean_c`, and `center_c`. If it is false, inspect `error`; do not treat null or offline values as measurements.

Sentinel → Sensors displays a **TOPDON TC001** card:

- Previews the thermal image and displays the maximum temperature across the full frame.
- Click the card to view a larger image, minimum/mean/center temperatures, and configure its name and alarm thresholds.
- Thresholds, the home page chart, and status change logs use the **maximum temperature across the full frame**.
- The card can appear alongside the ordinary camera, DS18B20, and door contact sensor.
- If disconnected or no new frame arrives for more than 3 seconds, endpoint temperatures are cleared and video stops. After reconnection, the background process retries, and the web page recovers after the next sensor poll.

Endpoints: `/api/thermal` (status), `/thermal_feed` (MJPEG), and `/api/sensors` (includes a temperature record with `id=thermal:tc001`). All clients share one acquisition thread, generating up to approximately 10 preview frames per second. Sensor readings retain the web page's 3-second refresh interval.

## Measurement and verification scope

The lower half of each frame is decoded as little-endian 16-bit data, with temperature converted using `raw / 64 - 273.15` °C. The color image is generated from the temperature matrix, with its scale adapting to the current frame's minimum and maximum temperatures. The displayed image is 512×384; actual thermal resolution remains 256×192. Invalid pixels appear black and are excluded from statistics. Clearly invalid temperature planes or incoming RGB data produce errors rather than fabricated temperatures.

This version uses a community-verified TC001 raw data format and has not yet been verified on your physical device. It does not implement the full emissivity, reflected temperature, and distance corrections available in the TOPDON app. After deployment, compare readings of the same target with TCView/TopInfrared before choosing experimental alarm thresholds.

Product information: [TOPDON TC001](https://www.topdon.com/products/tc001).
